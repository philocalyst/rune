# Opt-in owner-to-Window retained row example

`diagnostic_retained_row_window` is a separate example, not a normal CLI or FrameView activation. It uses the official platform `Application::new` and `open_window`, never a substitute display backend. Do not run it where display access is denied or absent. This environment has no DISPLAY or WAYLAND_DISPLAY; official GPUI headless cannot open a Window. The example has only been compiled, not executed with a Window.

A native bank is measured in the actual App. Its bank ID crosses to one independent owner thread, which owns a real immutable Session snapshot for `AVATAR`. It sends a bounded source request through the existing handoff. A foreground task owns the UI endpoint outside the Entity. It drains both request and receipt queues before awaiting activity. A request is shaped using the actual Window, bank and unchanged descriptor, retained in RowView, and replied to only after the Window/Entity update returns. Owner receipt is then retained and notifies the view. Render constructs the diagnostic Canvas from that same retained stage and receipt, with explicit dimensions. No replacement scalar shaping is used.

The owner checks an absolute deadline on every turn and closes the opposite endpoint after three seconds. UI close is observed through the activity channel. The foreground task closes its endpoint before joining the owner through the background executor, then schedules ordinary foreground quit. Endpoint calls are outside Entity/Window borrows; the owner Waker only unparks its thread. This is cooperative bounded transport shutdown, not a watchdog for a stuck SDK call, foreground executor, constructor, backend panic or process stall. An external process timeout remains necessary for future runtime qualification.

The unit test exercises the real Session owner request/reply/receipt/close path with an explicitly synthetic protocol token, not a native stage, FontId, coverage assertion or painter. The example's logical owner window ID is not an authenticated mapping to a GPUI Window identity; stage checks bind the actual UI stage to its real Window but do not grant owner geometry authority.

Future permitted runtime evidence must separately record Window creation, shape, correlated receipt, Canvas callback status, SDK paint return, scene/raster output and presented pixels. Console completion or PaintReturnedOk alone is not visual success. Coverage remains Unknown, SDK fallback/.notdef and race-after-live-check remain possible. SDK error may partially record scene; panic/OOM and mask-stack unwind are not contained. No editable-file, Lisp owner, Doom/Org, IME, hit-test, cursor or production-renderer parity is claimed.

## Reliable diagnostic outcome and render-attempt identity

The revised main returns ExitCode. The default is2 (completion never observed); setup, serve, owner/join or quit-scheduling errors return1. Zero requires successful UI protocol, successful owner completion, and PaintReturnedOk from the latest recorded render attempt. Zero still does not verify pixels, coverage or presentation.

Each Render invocation increments a checked local render-attempt number and clears the previous journal entry. A canvas is assigned a fresh NotInvoked Cell paired with that render number and the accepted stage token. An earlier canvas callback holds only its earlier Cell and cannot overwrite the current attempt. Render without stage/receipt or counter exhaustion leaves no current successful attempt. This is a logical Render invocation identity, NOT a GPUI frame ID or a guarantee that the frame was presented. The completion check is an observation, not atomic authorization against concurrent owner revocation.
